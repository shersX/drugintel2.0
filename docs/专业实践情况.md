## 二、论文中期进展情况

### 2.1 论文研究背景与目标

本论文针对医药竞争情报监测领域的信息过载和同质化问题，研究如何构建基于大模型的智能情报监测与推送系统。核心研究问题包括：如何从海量多源新闻中高效过滤医药相关情报、如何将同一事件的多篇报道自动聚合减少信息冗余、如何利用RAG技术提供高质量的领域问答服务、如何实现情报的主动监测与及时推送。

### 2.2 已取得的研究成果

#### 2.2.1 系统架构设计与实现

完成了基于大模型的医药竞争情报智能监测与推送系统的整体设计与实现，系统采用五层架构：

- **数据采集层**：实现了Bioon、GlobeNewswire、PRNewswire三个数据源的异步爬虫，支持增量抓取、错误重试、User-Agent轮换等机制
- **数据处理层**：设计了关键词初筛+LLM语义判断的两级过滤机制，实现了标题去重、向量去重、自动摘要生成等功能
- **数据存储层**：采用PostgreSQL+pgvector方案，支持结构化数据存储和向量相似度检索
- **业务逻辑层**：实现了事件聚类、RAG问答、告警推送等核心算法模块
- **前端应用层**：开发了Vue.js前端应用，提供事件展示、智能问答、监控管理等功能

#### 2.2.2 核心算法研究进展（一类创新点）

**增量式事件聚类算法**是本论文的核心创新点，针对医药情报监测的流式数据特点，提出了支持增量更新的多阈值链式聚类算法：

**问题定义**：传统聚类算法（如K-Means、DBSCAN）假设数据一次性全量可用，但在情报监测场景中，新闻是流式到达的，需要实时判断归属事件，且事件数量无法预先确定。

**方法创新**：

- 设计了分层阈值决策机制（θ\_high=0.90，θ\_mid=0.80），高阈值保证准确性，中阈值兼顾召回率
- 引入中心向量动态更新策略，新样本加入后按加权平均更新事件中心
- 实现了O(C)复杂度的增量判断（C为现有事件数），远优于批处理算法的O(N)或O(N²)

**与经典算法的本质区别**：

| 维度    | 传统批处理聚类 | 本文增量式聚类  |
| ----- | ------- | -------- |
| 数据假设  | 全量静态数据  | 流式到达数据   |
| 新样本处理 | 重新训练/重跑 | O(C)增量判断 |
| 预设参数  | 需预设K值   | 无需预设簇数   |
| 适用场景  | 离线分析    | 实时监测     |

#### 2.2.3 实验设计与准备工作

**数据集构建**：

- 从系统采集的医药新闻中筛选400-600条进行人工标注
- 制定了详细的标注规范：同一监管动作/临床结果/并购为同一事件，同一药物不同阶段为不同事件
- 已完成300条标注，标注者一致性达到85%，计划1周内完成全部标注

**对比实验设计**：

- 对比方法：标题去重（B1）、单阈值聚类（B2）、K-Means（B3）、DBSCAN（B4）
- 评价指标：ARI（主指标）、成对Precision/Recall/F1、轮廓系数、运行时间
- 消融实验：验证中心约束、分层阈值、动态更新三个组件的贡献

#### 2.2.4 其他模块研究进展

**RAG智能问答模块**：

- 实现了意图识别、混合检索（向量+全文RRF融合）、Cross-Encoder重排序、多轮对话管理等功能
- 设计了5类意图分类（news\_query、drug\_info、company\_query、general、comparison）
- 实现了WebSocket流式输出，提升了用户体验

**情报推送模块**：

- 实现了Watchlist订阅功能，支持药物、公司、关键词三种订阅类型
- 设计了基于事件聚类的增量推送触发机制，避免重复推送
- 实现了邮件模板和SMTP发送服务

### 2.3 存在的问题与困难

**金标准标注工作量大**：医药新闻的事件归属需要专业知识，标注者一致性需反复校准。目前已完成试标阶段，一致性达到85%，正在扩大标注规模。

**实验结果存在不确定性**：若聚类效果不够显著，可能需要调整评价角度，强调增量效率优势而非纯聚类质量。

**系统性能优化空间**：在海量数据场景下，向量检索性能可能需要进一步优化（如引入HNSW索引）。
