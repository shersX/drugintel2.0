## 二、论文中期进展情况

### 2.1 论文研究背景与目标

医药行业竞争情报来源广泛、更新频繁，涵盖监管公告、临床试验进展、企业并购、药物获批等多类资讯。情报人员需持续跟踪 数个新闻来源渠道，面临三方面突出矛盾：一是**信息过载**，日均新闻体量大，人工筛选成本高；二是**内容同质化**，同一事件常被多家媒体重复报道，难以快速把握事件全貌；三是**利用效率低**，传统关键词检索难以理解语义，无法支撑“问一句、得一句”的专业研判需求。因此，亟需构建能够自动采集、智能过滤、事件聚合、语义问答与主动推送的一体化监测体系。

在大语言模型与检索增强生成（RAG）技术快速发展的背景下，将语义理解、向量检索与生成式问答引入医药情报场景具有现实可行性：大模型可辅助判断新闻与医药领域的相关性并生成摘要；向量表示与混合检索可支撑高质量领域问答；增量式聚类可适应新闻流式到达的特点，实现同一事件的实时归并。本论文据此提出**基于AI的医药竞争情报智能监测与推送系统**的研究目标，力求形成从多源采集、智能处理到检索问答、订阅推送的端到端闭环。

围绕上述目标，本论文拟重点回答以下四个核心研究问题：

1. **情报过滤**：如何从海量多源新闻中高效识别并保留医药相关情报，降低噪声与冗余？
2. **事件聚合**：如何将同一事件的多篇报道自动归并，减少信息冗余、呈现事件级视图？
3. **领域问答**：如何利用 RAG 技术，结合混合检索与重排序，提供可溯源、高质量的医药领域问答服务？
4. **主动推送**：如何基于用户订阅与事件聚类结果，实现情报的主动监测与及时推送，避免重复通知？

#### 2.2.2 核心算法研究进展（一类创新点）

**说明**：本节内容为**算法层面的形式化建模、决策机制设计与复杂度分析**，作为论文一类创新点——**面向流式医药情报的增量式多阈值链式聚类算法（Incremental Multi-Threshold Chaining Clustering，下文简称 IMTC）**——的研究基础。

##### 2.2.2.1 问题形式化

设第 t 时刻新到达的医药新闻经 BGE-M3 嵌入后得到语义向量 **x**t ∈ ℝd；系统已在线维护事件簇集合：

```
E(t) = { E₁, E₂, …, E_{C_t} }，  E_i = ⟨ s_i, c_i, n_i ⟩
```

其中 **s**i 为**种子向量**（seed），**c**i 为**动态簇中心向量**（centroid），ni 为簇内样本数。算法目标是在 O(Ct·d) 时间内确定归属决策：

```
Φ(x_t) ∈ { 1, 2, …, C_t, C_t + 1 }
```

其中末项对应「创建新事件簇」，并同步将簇结构在线更新为 E(t+1)，使全局聚类一致性指标（ARI 与成对 F1）在医药领域语义空间下达到 Precision–Recall 的最优均衡。

该问题面临四方面核心挑战：

- **流式可见性约束**：数据按时间序列单次访问，禁止多轮回放，传统批处理目标函数无法直接最优化；
- **簇基数未知**：事件数 Ct 随时间增长且无法预设上界，K-Means 类参数化方法不适用；
- **语义漂移**：同一事件在不同报道中存在中英文混合、转载改写等表述差异，单一相似度阈值难以兼顾召回与准确；
- **细粒度异源辨识**：同一药物在不同审批阶段或临床结果应判为**异源事件**，要求决策机制具备亚事件级判别能力。

##### 2.2.2.2 核心思想：分层阈值决策与种子—中心双锚约束

对最佳候选簇 i* = argmaxi cos(**x**t, **c**i)，构建三段式判决空间：

```
Φ(x_t) =
  ├─ i*，  若 cos(x_t, c_{i*}) ≥ θ_high                          【高置信归簇】
  ├─ i*，  若 θ_mid ≤ cos(x_t, c_{i*}) < θ_high 且 cos(x_t, s_{i*}) ≥ θ_mid  【双锚约束归簇】
  └─ C_t+1，  其他情况                                            【新建事件簇】
```

其中 θhigh = 0.90、θmid = 0.80。第一分支由中心向量直接判定，保障 Precision；第二分支须额外通过种子向量**双锚约束**二次校验，在中等相似度区间补足 Recall；第三分支触发**新事件创建**。

定义簇 Ei 的有效接纳域 Ri 为：

```
R_i = { x | cos(x, c_i) ≥ θ_high ∨ ( cos(x, c_i) ≥ θ_mid  ∧  cos(x, s_i) ≥ θ_mid ) }
```

该接纳域是「中心高置信球」与「种子—中心交集球」的并集，使簇在线扩张过程中始终围绕「首报道事件语义」保持紧致性，抑制**话题漂移簇**（topic drift cluster）。

##### 2.2.2.3 中心向量在线更新与收敛性

对归入簇 Ei 的新样本 **x**t，采用**容量加权平均**更新中心，并视需要做单位化处理：

```
c_i ← ( n_i · c_i + x_t ) / ( n_i + 1 )，   n_i ← n_i + 1
```

该更新在 O(d) 时间内完成，无需保留历史样本，符合流式场景对常数空间的硬约束。进一步可证：当 ni 增长时，单条新样本对中心的边际影响为

```
‖Δc_i‖ = (1 / (n_i + 1)) · ‖x_t − c_i‖ = O(1 / n_i)
```

即随簇成熟度增加而递减，使中心向量天然收敛、抑制后期噪声样本对早期事件中心的过度扰动，形成「**事件越成熟，中心越稳定**」的自适应稳态特性。

##### 2.2.2.4 时间—空间复杂度分析

设流式样本总数为 N，事件峰值簇数为 Cmax，嵌入维度为 d，则 IMTC 的关键算子开销可分析如下：


| 关键算子           | 时间复杂度       | 空间复杂度     | 说明          |
| -------------- | ----------- | --------- | ----------- |
| 单次归属判决         | O(Ct·d)     | O(1)      | 与全部簇中心做余弦比较 |
| 中心动态更新         | O(d)        | O(1)      | 容量加权平均      |
| 簇结构在线维护        | O(1)        | O(Ct·d)   | 仅持久化中心与种子   |
| **N 条流式数据总开销** | O(N·Cmax·d) | O(Cmax·d) | 满足 Cmax ≪ N |


对照而言，K-Means 在新增样本时全量重训均摊代价为 O(N·K·d·titer)；DBSCAN 在不构建邻域索引时退化为 O(N²·d)。**医药情报场景中事件基数远小于样本数（Cmax ≪ N）**，IMTC 在该稀疏聚类条件下具备显著渐进效率优势。

##### 2.2.2.5 与经典方法的本质差异


| 维度                  | 全量批处理（K-Means / DBSCAN） | 单阈值贪心链式聚类 | **本文 IMTC** |
| ------------------- | ----------------------- | --------- | ----------- |
| 数据可见性假设             | 全量静态                    | 流式        | 流式          |
| 簇数 K 是否需预设          | K-Means 需 / DBSCAN 不需   | 不需        | 不需          |
| 新样本处理代价             | O(N) 或 O(N²)            | O(C)      | O(C·d)      |
| 决策机制                | 全局目标函数最优化               | 单阈值贪心     | 分层阈值 + 双锚约束 |
| 簇内语义紧致性             | 受全局结构主导                 | 易随中心漂移扩散  | 种子约束抑制漂移    |
| Precision/Recall 调控 | 不直接可控                   | 阈值二选一权衡   | 双阈值独立可调     |
| 中心稳定性               | 受全局重训影响                 | 无界漂移      | O(1/ni) 自收敛 |
| 典型适用场景              | 离线挖掘分析                  | 实时但精度受限   | 实时高精度监测     |


##### 2.2.2.6 创新点定位与贡献

综上，IMTC 算法在以下三个维度形成**机制级创新**：

1. **场景适配创新**：将语义嵌入向量空间与流式增量聚类范式结合，针对医药情报「事件数稀疏、语义紧致、时效敏感」的领域特性给出端到端可行方案，区别于通用领域以全量批处理或固定 K 假设为基础的传统方法；
2. **决策机制创新**：以**分层阈值 × 种子—中心双锚**取代单阈值贪心或单中心策略，从机制层面缓解了流式聚类中长期存在的 Precision–Recall 权衡难题，并赋予系统在不同业务紧迫度下灵活配置双阈值的能力；
3. **效率与可扩展性创新**：维持单样本 O(C·d) 时间复杂度与 O(C·d) 空间复杂度，自然支持 7×24 小时在线响应，并为后续引入近似最近邻索引（如 HNSW、IVF-PQ）做工业级扩展预留了接口位。

上述算法层面工作已完成**形式化建模、判决机制构造、复杂度推导与对照分析**；具体的系统接入实现、超参数寻优、对比与消融实验详见 2.2.3 后续计划。

### 2.3 存在的问题与困难

中期阶段系统在架构设计与核心链路上取得进展的同时，仍面临工程稳定性、实验验证与能力补全等多方面的制约。主要问题与困难如下。

**（1）多源爬虫抓取速率与正文完整性问题**

当前三源爬虫账号封禁压力可控，但仍有验证码/人机校验拦截，以及 JS 异步渲染导致“有标题无正文”的残缺抓取，影响后续 AI 处理质量。该问题本质是采集层数据完整性风险。拟通过 Playwright 动态渲染、验证码处理预留、正文校验与补抓重试机制进行优化。

**（2）核心链路尚非全系统闭环**

目前已打通 **采集 → 处理 → PostgreSQL 入库** 主链路，但 pgvector 检索、事件聚类、RAG、前端与邮件推送仍处于【方案设计】或【待开展】阶段，尚未形成完整业务闭环。后续将按“向量能力落地 → 聚类接入 → RAG 迁移 → 前端联调”分阶段推进，降低集成风险。

**（3）算法实验与一类创新点的量化验证滞后**

IMTC 算法已完成形式化建模与复杂度分析，但**金标准数据集人工标注**以及相对 B1–B4 基线方法的**对比实验、消融实验**尚未启动，聚类创新点尚缺乏 ARI、成对 F1 等指标的实测支撑，存在「理论设计充分、实验证据不足」的风险。医药新闻事件归属需领域知识，标注成本与标注者一致性校准工作量较大。若主实验指标不够显著，拟从**增量处理效率**、**流式场景可用性**等维度补充论证，并与 2.2.3 实验计划衔接。

**（4）RAG 能力「实践—论文」双轨衔接**

企业实践项目一已在 **MongoDB + Milvus** 环境下验证混合检索与 Cross-Encoder 重排序；论文系统规划采用 **PostgreSQL + pgvector** 统一存储。两套技术栈在向量索引类型、检索 API、切片入库流程上存在差异，迁移接入时需重新设计适配层（嵌入写入、Top-K 检索、RRF 融合接口等），并重新完成联调与效果对比，**存在一定工程工作量与效果不确定性**。

**（5）系统性能与规模扩展的前瞻性挑战**

随采集数据量持续增长，将在向量检索延迟、聚类时与全部事件中心的相似度计算开销、批量向量化任务占用等方面面临性能压力。pgvector 在百万级向量场景下可能需要 **HNSW** 等索引参数调优；Celery 异步任务队列接入后还需验证爬虫、批处理与 API 服务之间的资源争用。上述问题目前尚处于**方案预见阶段**，将在核心功能闭环跑通后开展针对性压测与优化。

### 2.4 下一步工作计划
