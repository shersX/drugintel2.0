# 专业实践情况

## 一、实践技能训练及提升情况、参与专业实践情况

### 1.1 专业技术能力训练

在研究生阶段的系统学习与课题实践中，本人围绕"基于大模型的医药竞争情报智能监测与推送"课题，完成了从方案设计到系统落地的全过程训练，专业技术能力得到显著提升：

**编程开发与工程实现能力**：在本课题系统开发中，系统掌握了 Python 异步编程（asyncio）、FastAPI、SQLAlchemy 等现代 Web 开发技术栈。在数据采集模块中，实现了 Bioon、GlobeNewswire、PRNewswire 等多源新闻的异步并发抓取，处理了连接池管理、请求重试、反爬规避等工程问题；在后端开发中，完成了 RESTful API 设计与实现，并实践了 Redis 缓存、Celery 异步任务调度等性能优化手段。

**人工智能与大数据应用能力**：围绕论文核心需求，深入应用文本嵌入模型（BGE-M3）、向量数据库（pgvector）与检索增强生成（RAG）等技术。完成了新闻语义过滤、向量去重、增量式事件聚类、混合检索与重排序等关键环节的工程实现，形成了"数据预处理—特征表示—语义检索—生成回答"的完整 AI 应用链路，具备了将算法方案转化为可运行系统的能力。

**数据库与系统架构设计能力**：独立完成了 PostgreSQL 数据库 schema 设计，集成 pgvector 扩展以支持向量相似度检索；搭建了 Redis 缓存层与 Celery 分布式任务队列，构建了数据采集—处理—存储—检索—推送的五层系统架构。在此过程中，积累了索引优化、任务调度、容器化部署等中大型 Web 系统的工程实践经验。

### 1.2 专业实践活动参与情况

在研究生阶段，本人先后独立负责三项医药信息化方向的工程实践项目，涵盖情报采集与智能问答、科研审核自动化、企业知识库搭建等场景，积累了从需求分析、系统设计到部署落地的完整实践经验。

**项目一：医药信息 AI 竞争情报搜集与 RAG 智能问答系统**

针对医药行业公开资讯分散、竞品数据人工采集成本高、情报难以快速检索答疑等痛点，本人独立负责搭建自动化医药情报采集与智能问答系统，实现情报抓取、结构化存储、向量入库、智能问答的全链路闭环。在数据采集层面，采用 Scrapy 结合 Playwright 动态渲染，完成药企公告、药品审批、临床试验等多维度情报采集，覆盖 20 余个医药行业数据源；同时搭建代理 IP 池，结合随机请求头、请求间隔抖动与退步重试策略，将爬虫存活率提升至 95% 以上。在数据存储层面，设计 PostgreSQL + Milvus 双库架构，分别承载结构化业务数据与文本向量，兼顾精确查询与语义检索需求。在智能问答层面，基于 FastAPI 搭建 RAG 问答服务，融合 Milvus 向量检索与 BM25 关键词检索，经 RRF 融合与 Cross-Encoder 重排序后生成回答，并支持 SSE 流式输出与问答溯源功能。系统最终通过 Docker Compose 完成 FastAPI、Milvus、PostgreSQL 的一键容器化部署，开发环境与生产环境相互隔离。

**项目二：科研课题自动化审核系统（后端 API）**

针对传统医药科研课题审核依赖人工、标准繁琐、周期长且易错审漏审的问题，本人独立负责基于大模型 NLP 技术搭建智能审核 API，实现课题材料的自动化合规校验与风险识别。首先拆解 49 条课题审核业务规则，划分格式规范、项目基本面、内容方案、产出、申请人与经费六大审核维度，构建适配基金科研申报场景的标准化审核流程；随后采用 Few-Shot 提示词工程约束模型输出，定制专属审核 Prompt，将审核结果准确率提升至 95%。在数据处理方面，使用 pypdf 解析上传 PDF 正文，结合规则引擎完成分段、截取与要点抽取，实现结构化语料的标准化输入；在服务部署方面，封装高可用审核 API，统一请求参数、异常捕获与超时重试机制，优化大模型调用并发问题。系统上线后将人工审核时长由平均 30 分钟/篇缩短至 30 秒，大幅降低了审核人力成本，实现了审核标准统一与结果可溯源。

**项目三：基于 Dify 的企业内部智能知识库搭建**

针对医药代表业务中产品、管线、中标等信息分散、查询效率低的问题，本人独立负责基于 Dify 低代码 AI 平台搭建私有化智能知识库，实现文档托管、智能检索与专业问答。在知识入库环节，摒弃单一通用切分规则，依据文档类型定制差异化切分策略：临床实验文档采用全文父子文段，PDF/PPT 宣传文件采用父子分段切分，极度复杂的文档则经 MinerU 预处理统一转化为 Markdown 后入库。在问答服务环节，定制专属提示词模板，开启引用溯源功能，精准标注文档出处，规避大模型幻觉，保障专业问答内容严谨可追溯；同时在 Dify 后台自定义 RAG 检索策略，优化向量权重计算规则，有效提升了企业内部知识检索的准确率与响应效率。

## 二、论文中期进展情况

### 2.1 论文研究背景与目标

本论文针对医药竞争情报监测领域的信息过载和同质化问题，研究如何构建基于大模型的智能情报监测与推送系统。核心研究问题包括：如何从海量多源新闻中高效过滤医药相关情报、如何将同一事件的多篇报道自动聚合减少信息冗余、如何利用RAG技术提供高质量的领域问答服务、如何实现情报的主动监测与及时推送。

### 2.2 已取得的研究成果

#### 2.2.1 系统架构设计与实现

完成了基于大模型的医药竞争情报智能监测与推送系统的整体设计与实现，系统采用五层架构：

- **数据采集层**：实现了Bioon、GlobeNewswire、PRNewswire三个数据源的异步爬虫，支持增量抓取、错误重试、User-Agent轮换等机制
- **数据处理层**：设计了关键词初筛+LLM语义判断的两级过滤机制，实现了标题去重、向量去重、自动摘要生成等功能
- **数据存储层**：采用PostgreSQL+pgvector方案，支持结构化数据存储和向量相似度检索
- **业务逻辑层**：实现了事件聚类、RAG问答、告警推送等核心算法模块
- **前端应用层**：开发了Vue.js前端应用，提供事件展示、智能问答、监控管理等功能

#### 2.2.2 核心算法研究进展（一类创新点）

**增量式事件聚类算法**是本论文的核心创新点，针对医药情报监测的流式数据特点，提出了支持增量更新的多阈值链式聚类算法：

**问题定义**：传统聚类算法（如K-Means、DBSCAN）假设数据一次性全量可用，但在情报监测场景中，新闻是流式到达的，需要实时判断归属事件，且事件数量无法预先确定。

**方法创新**：

- 设计了分层阈值决策机制（θ\_high=0.90，θ\_mid=0.80），高阈值保证准确性，中阈值兼顾召回率
- 引入中心向量动态更新策略，新样本加入后按加权平均更新事件中心
- 实现了O(C)复杂度的增量判断（C为现有事件数），远优于批处理算法的O(N)或O(N²)

**与经典算法的本质区别**：

| 维度    | 传统批处理聚类 | 本文增量式聚类  |
| ----- | ------- | -------- |
| 数据假设  | 全量静态数据  | 流式到达数据   |
| 新样本处理 | 重新训练/重跑 | O(C)增量判断 |
| 预设参数  | 需预设K值   | 无需预设簇数   |
| 适用场景  | 离线分析    | 实时监测     |

#### 2.2.3 实验设计与准备工作

**数据集构建**：

- 从系统采集的医药新闻中筛选400-600条进行人工标注
- 制定了详细的标注规范：同一监管动作/临床结果/并购为同一事件，同一药物不同阶段为不同事件
- 已完成300条标注，标注者一致性达到85%，计划1周内完成全部标注

**对比实验设计**：

- 对比方法：标题去重（B1）、单阈值聚类（B2）、K-Means（B3）、DBSCAN（B4）
- 评价指标：ARI（主指标）、成对Precision/Recall/F1、轮廓系数、运行时间
- 消融实验：验证中心约束、分层阈值、动态更新三个组件的贡献

#### 2.2.4 其他模块研究进展

**RAG智能问答模块**：

- 实现了意图识别、混合检索（向量+全文RRF融合）、Cross-Encoder重排序、多轮对话管理等功能
- 设计了5类意图分类（news\_query、drug\_info、company\_query、general、comparison）
- 实现了WebSocket流式输出，提升了用户体验

**情报推送模块**：

- 实现了Watchlist订阅功能，支持药物、公司、关键词三种订阅类型
- 设计了基于事件聚类的增量推送触发机制，避免重复推送
- 实现了邮件模板和SMTP发送服务

### 2.3 存在的问题与困难

**金标准标注工作量大**：医药新闻的事件归属需要专业知识，标注者一致性需反复校准。目前已完成试标阶段，一致性达到85%，正在扩大标注规模。

**实验结果存在不确定性**：若聚类效果不够显著，可能需要调整评价角度，强调增量效率优势而非纯聚类质量。

**系统性能优化空间**：在海量数据场景下，向量检索性能可能需要进一步优化（如引入HNSW索引）。
