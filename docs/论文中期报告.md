#### 1.2.2 核心算法实现（T4，核心创新点）

**增量式事件聚类算法**已完成实现：

```python
# 算法核心逻辑
def incremental_cluster(news_embedding, existing_events):
    """
    增量式事件聚类决策
    输入：新新闻向量，现有事件列表
    输出：归属事件ID或新建事件
    """
    # Step 1: 计算与所有事件中心的相似度
    similarities = [cos_sim(news_embedding, e.centroid)
                    for e in existing_events]
    max_sim = max(similarities)
    best_event = existing_events[argmax(similarities)]

    # Step 2: 分层阈值决策
    if max_sim >= THETA_HIGH:
        # 高置信度直接入簇
        return assign_to_event(best_event, news_embedding)
    elif max_sim >= THETA_MID:
        # 中置信度需双重验证
        seed_sim = cos_sim(news_embedding, best_event.seed)
        if seed_sim >= THETA_MID:
            return assign_to_event(best_event, news_embedding)

    # Step 3: 创建新事件
    return create_new_event(news_embedding)
```

**算法特点**：
- 无需预设事件数量K
- 新样本处理复杂度O(C)，C为现有事件数
- 支持中心向量的动态更新

## 二、核心创新点阐述

### 2.1 学术问题定义

**问题**：医药情报监测场景下，如何对新到达的新闻进行实时事件聚合？

**现有方法的局限**：

| 方法类型 | 局限 |
|----------|------|
| 标题精确去重 | 无法处理改写稿、翻译稿 |
| K-Means聚类 | 需预设K值，无法增量更新 |
| DBSCAN聚类 | 批处理模式，新数据需全量重跑 |
| 单阈值贪心聚类 | 阈值选择两难（准确vs召回） |

### 2.2 本文方法：增量式多阈值链式聚类

**核心思想**：针对流式数据特点，设计支持增量更新的聚类机制。

**三阶段决策流程**：

```
新新闻到达
    ↓
计算与所有事件中心的相似度
    ↓
┌────────────────────────────────────────┐
│ 相似度 ≥ θ_high?                       │
│  是 → 直接入簇，更新中心                │
│  否 → 进入第二阶段                     │
└────────────────────────────────────────┘
    ↓
计算与种子向量的相似度
    ↓
┌────────────────────────────────────────┐
│ 相似度 ≥ θ_mid 且 与中心相似度 ≥ θ_mid? │
│  是 → 入簇，更新中心                    │
│  否 → 创建新事件                        │
└────────────────────────────────────────┘
```

**与经典算法的本质区别**：

| 维度 | 传统批处理聚类 | 本文增量式聚类 |
|------|---------------|----------------|
| 数据假设 | 全量静态数据 | 流式到达数据 |
| 新样本处理 | 重新训练/重跑 | O(C)增量判断 |
| 预设参数 | 需预设K值 | 无需预设簇数 |
| 适用场景 | 离线分析 | 实时监测 |

### 2.3 创新点总结

**一类创新**：针对医药情报流式监测场景，提出了支持增量更新的多阈值链式聚类算法，解决了传统批处理聚类无法实时处理新数据的问题。

## 四、存在的问题与困难

### 4.1 金标准标注工作量大

**问题**：医药新闻的事件归属需要专业知识，标注者一致性需反复校准。

**解决方案**：
- 已完成30条试标，标注者一致性达到85%
- 采用双人交叉标注+仲裁机制
- 优先保证质量，规模可调整至400条

### 4.2 实验结果存在不确定性

**问题**：若实验结果不够显著，可能无法支撑"一类创新"的宣称。

**应对措施**：
- 设计多维度评价指标（ARI、F1、运行时间）
- 准备消融实验充分展示各组件贡献
- 备选方案：强调增量效率优势（运行时间对比）

### 4.3 与其他模块的关联论证

**问题**：需要说明聚类模块如何服务于下游RAG和推送功能。

**解决方案**：
- RAG检索时按事件去重，减少上下文冗余
- 推送时利用聚类结果避免重复通知
- 准备系统级实验验证端到端效果
